## Risks

- **R-01 — Backlog estimate drift is systemic (primary).** BL-013 (8→3) and BL-014 (13→2) were ~95% done; BL-015 (5→3) and BL-018 (done) before them. **The backlog cannot be trusted for planning without a code audit.** Mitigation: the headline followup is a **backlog-reconciliation pass** (audit every `in-progress`/`planned` story against code, flip statuses, re-estimate); until then, every committed story is verified against code at kickoff. This sprint's core is intentionally small and buffer-heavy to absorb further "already-done" surprises.
- **R-02 — BL-012 alerts coupling.** `_seed_alerts` couples to the monitoring worker; removing it naïvely can blank the Alert Feed. Mitigation: remove independent seeds (`conversations`, `workflows`, `evidence_packs`, cases-vestige) first; remove `alerts` only after the monitoring-generated durable read path is confirmed.
- **R-03 — BL-014 corpus + LLM nondeterminism.** The demo's RAG assertion depends on LLM extraction/answering, which is nondeterministic on a local model. Mitigation: assert on *grounded structure* (citations present, expected entities in the graph) rather than exact answer text; the existing e2e variants already follow this pattern.
- **R-04 — Capacity & calendar drift.** Work continues to land far ahead of nominal windows (BL-011's 8 SP shipped in one session). The 25 SP and 07-07→07-20 dates are nominal. Mitigation: re-baseline from actual 2026-22..25 merge-date throughput before 2026-26 (carries forward).
