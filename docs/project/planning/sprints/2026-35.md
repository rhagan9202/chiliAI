## Deviations from the plan — all three were the right call

The plan prescribed three fixes that would not have worked. Each was rejected by
its implementer, verified, and replaced:

1. **`BL-054` (stage timeout).** The plan said "do not ACK a timed-out delivery."
   `XAUTOCLAIM` reclaims from any consumer including the worker's own, so an
   un-ACKed delivery would be redelivered every 60s, spawning a new executor
   thread each time until the pool exhausted. Worse, a slow-but-healthy stage
   finishing after the threshold would be re-run and **re-publish its successor
   event**, re-running the whole downstream pipeline. Replaced with "timeout is
   an alarm, not a deadline": the budget is applied without cancelling, the
   overrun is logged, and the handler is awaited so the ACK reflects the real
   outcome.
2. **`BL-056` (request size).** The plan put a `Content-Length` check in the
   handler. FastAPI buffers and decodes the body before handler code runs
   (`routing.py:430-446` vs `solve_dependencies` at 481), so it would have fired
   after the memory spike it existed to prevent. Replaced with a custom
   `APIRoute` wrapping the ASGI `receive()` channel.
3. **`BL-058` (migration 0020 downgrade).** The plan had the downgrade silently
   `DELETE` duplicate rows. Playbook snapshots are documented immutable history
   and no other migration in the tree deletes rows. Replaced with a loud `RAISE`
   naming what the operator must resolve.

## What the process caught

Nine of the twenty-three controller rulings were corrections to the plan itself,
not to implementers' work — including a `close()` that would have silently
no-opped for three of five resources, and three tests that could not have failed
for the right reason.

**The decisive finding was against the one unreviewed commit.** Every task commit
went through an independent spec-and-quality review. `b8e1ffef` did not, because
it predated the sprint. The final whole-branch review found three critical
regressions in it, the worst of which silently dropped fraud alerts for every
entity after the first in a batch — `risk.scored` inherited the pipeline
correlation id, and being a terminal-success event type, the first one closed the
run so every later one was skipped. Thirteen reviewed commits produced zero
criticals; the one unreviewed commit produced three. All were fixed before merge.
