## File: docs/backlog/embeddings.md

**Scope:** Synchronous text + graph-channel embedding generation for `backend/embeddings/` and the composition wiring that constructs embedders in `backend/api/dependencies.py` and `backend/agent/coordinator.py`. Covers adapter parity (in-memory, OpenAI, sentence-transformers), throughput (batching), provider observability and cost tracking, model lifecycle (versioning, backfill, fine-tuning), caching, dimension governance, and cold-start performance for locally-loaded models. Excludes vector storage/indexing (owned by `vectorstore.md`) and RAG query-side embedding orchestration (owned by `rag.md`).

### Epics
1. Add `EmbedderProtocol` introspection and health-check surfaces — `EmbedderProtocol.embed` is the only method, with a `TODO(production)` noting that `get_model_info()` / `health_check()` are still missing, so the API readiness probe and config-validation paths cannot ask an embedder what model/dimensions it serves or whether it is reachable (`backend/embeddings/adapters/protocols.py:11-22`).
2. Add a configurable embedding cache to avoid re-embedding identical text — `EmbeddingsService.embed` always invokes the adapter and the service-level `TODO(production)` calls out the absence of a content-hash cache; re-uploads, deduplicated records, and repeated RAG queries pay full provider cost every time (`backend/embeddings/service.py:20-49`).
3. Add provider-side retry/backoff and rate-limit handling for non-OpenAI adapters — Only `OpenAIEmbedder._create_embeddings_with_retry` implements exponential backoff for 429s; `SentenceTransformersEmbedder` and `InMemoryEmbedder` have no retry surface, and the service-level `TODO(production)` flags this gap for batch chunking, retries, and token-budget enforcement (`backend/embeddings/adapters/openai_adapter.py:115-138`, `backend/embeddings/adapters/sentence_transformers_adapter.py:65-83`).
4. Add embedding observability — latency, batch size, vector count, error class — `EmbeddingsService` and adapters emit no metrics, traces, or structured logs; coordinator only emits `observe_pipeline_stage` at the workflow level, so per-provider latency/error breakdown is invisible (`backend/embeddings/service.py:38-105`, `backend/embeddings/adapters/openai_adapter.py:80-138`).
5. Add embedding cost tracking per provider — OpenAI billable input tokens are estimated only for batching (`_estimate_tokens`); no cost counter, per-request token usage, or per-KB roll-up is recorded for OpenAI or sentence-transformers, so spend cannot be attributed (`backend/embeddings/adapters/openai_adapter.py:225-228`, no equivalent in `service.py`).
6. Track embedding model version on every vector and add a backfill workflow — `EmbeddingMetadata` carries `model_name` but the model identity is not stamped onto persisted vectors as an immutable `model_version` and there is no job that re-embeds existing content when the configured model changes; vectors generated under different model versions silently mix in the same collection (`backend/embeddings/models.py:45-52`, `backend/embeddings/models.py:54-71`).
7. Govern embedding dimensions across providers and vector store — `EmbeddingsConfig.dimensions` defaults to 384 and the schema validator only cross-checks vector-store dimension when both sections are configured; no preflight verifies that the configured embedder actually returns that dimension, so a mis-set `sentence_transformers` model can crash at first batch (`backend/config/schema.py:128-137`, `backend/config/schema.py:403-411`, cross-edge to `vectorstore.md`).
8. Add a model registry / multi-model routing surface — `EmbedRequest.model_name` is captured but `get_embedder()` is `@lru_cache(maxsize=1)` and the service holds one embedder, so requests cannot select between configured models at call time; the `TODO(production)` calls out model routing as a gap (`backend/api/dependencies.py:531-572`, `backend/embeddings/service.py:20-49`, `backend/embeddings/service_models.py:25-42`).
9. Cache and warm sentence-transformers model loads to remove cold-start latency — `_load_sentence_transformer_model` runs `importlib.import_module` and constructs `SentenceTransformer(model_name)` on first adapter instantiation; there is no model-download cache directory, eager-load hook, or readiness gate so the first request after worker start blocks on a fresh HuggingFace download (`backend/embeddings/adapters/sentence_transformers_adapter.py:119-149`, `backend/api/dependencies.py:541-551`).
10. Add a model fine-tuning hook for the §14.2 model-training pipeline — Nothing exists yet; `architecture.md §14.2` lists "embedding fine-tuning" as Medium-priority and the embeddings module has no `FineTuningJobProtocol`, no artifact contract for trained weights, and no swap-in path for a fine-tuned local model (`backend/embeddings/` has no training subpackage; `docs/architecture.md:1358`).
11. Add live provider parity smoke tests in CI — Only `OpenAIEmbedder` and `SentenceTransformersEmbedder` have integration smoke documented in `backend/embeddings/README.md`; CI has no profile that runs them with real credentials/models, so per-provider regressions (auth, dimension drift, batching) only surface in prod (`backend/embeddings/README.md:38-51`, `backend/tests/embeddings/test_openai_adapter.py`, `backend/tests/embeddings/test_sentence_transformers_adapter.py`).
12. Persist embedding artifacts to object storage for reproducibility — Service-level `TODO(production)` flags that `EmbeddingResult` is built and returned but never persisted; `handle_embeddings_complete` indexes vectors and discards the artifact, so re-running the workflow requires recomputation and there is no audit trail of what vectors were generated when (`backend/embeddings/service.py:20-105`, `backend/agent/coordinator.py:1761-1864`).

- Track embedding model version and add backfill depends on a backfill job runner in `agent.md` — re-embedding existing KB content is a worker workflow, not a request-time path.
- Track embedding model version and add backfill depends on persisted-vector schema fields in `vectorstore.md` — the version stamp has to round-trip through indexed vector metadata.
- Add a configurable embedding cache depends on a cache backend in `_infra.md` (Redis or KV cache) and on hash/content-id contracts in `shared.md`.
- Add embedding observability depends on the telemetry stack and metric naming in `_observability.md` — exporter, attribute conventions, and sampling live there.
- Add embedding cost tracking depends on the cost-attribution surface in `_observability.md` — per-tenant/per-KB roll-up shares plumbing with LLM cost.
- Add a model fine-tuning hook depends on the model-training pipeline in `analytics.md` (gnn fine-tuning is a sibling) and on object-storage artifact contracts in `storage.md`.
- Cache and warm sentence-transformers model loads depends on worker readiness in `agent.md` (epic 9 — split liveness/readiness) — the warm-up hook needs a readiness gate to delay traffic.
- Add live provider parity smoke tests depends on the secrets/credential profile in `_cicd.md` — CI needs OPENAI_API_KEY and a HuggingFace cache to run them.
- Add provider-side retry/backoff for non-OpenAI adapters depends on the shared retry primitive in `shared.md` (if extracted) — otherwise each adapter re-implements backoff.
- Persist embedding artifacts to object storage depends on object-storage adapter contracts in `storage.md` and the artifact-key conventions used by `handle_embeddings_complete` in `agent.md`.

### Open questions
- Should the embedding cache live behind a new `EmbeddingCacheProtocol` inside `backend/embeddings/` (keeping the module self-contained) or reuse a shared KV cache surface that `llm` will also need? The §14.2 endgame implies a single cross-module cache abstraction.
- Is `model_version` a free-form string captured from the provider (OpenAI's snapshot id, sentence-transformers commit hash) or a chiliAI-managed monotonic version? Backfill triggering depends on equality semantics.
- Does the fine-tuning hook produce a local sentence-transformers checkpoint persisted under `storage` and loaded by `SentenceTransformersEmbedder` via a model path, or does it produce a registry entry consumed by a new `FineTunedLocalEmbedder` adapter? The embeddings 1.0 spec explicitly defers learned training and does not pick.
- Should multi-model routing be a request-time `model_name` switch (caller picks) or a config-time per-KB binding (KB → embedder)? Vectorstore collections are dimension-pinned per KB today, which suggests per-KB binding is the safer first cut.
- Should the dimension preflight live in `EmbeddingsService` (running a dummy `embed(["__preflight__"])` at startup) or in the config loader (declarative match against a known model→dimension table)? Both have failure modes — the first incurs provider cost on every boot, the second hard-codes a table that drifts.
