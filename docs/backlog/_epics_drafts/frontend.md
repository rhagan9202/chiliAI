### Provisional cross-file edges
- Migrate seeded Dashboard/RAG read models depends on live analytics and RAG projections — corresponding gaps live in `analytics.md` (overview projection) and `rag.md` (service-backed conversational endpoint).
- Build a Configuration UI wizard depends on the `PUT /config/domain` endpoint and a hot-reload contract — the API+config epics live in `api.md` and `config.md`.
- Wire the persisted evidence-pack surface depends on the persisted-pack endpoint epic in `api.md` and `rag.md` (evidence assembly) — frontend cannot render packs the backend does not persist.
- Recover from missed SSE workspace events depends on a sequence-numbered/resumable workspace stream — the contract lives in `api.md` and `events.md`.
- Add a frontend RUM + JS-error tracking integration depends on the cross-cutting observability stack in `_observability.md` — exporter, DSN, and sampling are owned there.
- Add a TopBar tenant switcher and persist active tenant depends on tenant scoping in `_multitenancy.md` and tenant-aware auth claims in `_security.md`.
- Complete auth UI surface depends on RBAC claim shape and session-expiry headers in `_security.md` and `api.md`.
- Adopt the generated OpenAPI client depends on backend OpenAPI hardening epics in `api.md` — schema must be stable, versioned, and exported before frontend codegen is reliable.
- Run automated accessibility audits in CI depends on the CI surface in `_cicd.md` — axe and Lighthouse steps wire into the existing GitHub Actions workflow.
- Performance-harden the graph explorer depends on a backend neighborhood pagination contract in `api.md` and `graph.md` — frontend cannot cap rendered nodes without a server-side window/limit.
- Add pagination / cursor controls depends on cursor-shaped list responses across `api.md` (alerts, cases, workflows, KBs).
- Expand Playwright coverage depends on backend test fixtures and seed scripts in `_cicd.md` for full-stack flows where mocks are insufficient.
- Replace lists-only Investigation rendering with `GraphCanvas` depends on contract alignment in `api.md`/`graph.md` so neighborhood payloads expose the `SubgraphResult` shape `GraphCanvas` already consumes.

- Where does workspace-tenant context live in the URL/storage once `_multitenancy.md` lands — TopBar selector with localStorage, subdomain, or path prefix? Decision affects router shape and KB query keys.
- Does the persisted evidence-pack entry point belong on the Investigation Workbench, Alert Feed row, or its own `/evidence-packs` route? Architecture §14.3 lists "Complete persisted evidence-pack surface" as the next frontend milestone but does not specify placement.
