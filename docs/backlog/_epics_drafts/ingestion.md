## File: docs/backlog/ingestion.md

**Scope:** Document ingestion pipeline — registration, parsing, chunking, LLM/pattern extraction, validation, and provenance for the document flow (Flow A). Excludes the parallel `records/` tabular pipeline (its own backlog file) and downstream graph/vector writes (cascade-delete contracts are covered, but storage internals are in `graph.md` / `vectorstore.md`).

### Epics

1. **Reconcile architecture.md §14.3 HTML-parser entry with the live registration.** Doc states HTML parser registration is a "Next milestone" but `HtmlParser` ships in `backend/ingestion/parsers/registry.py:47-57` and `parsers/html.py:99-125`. Either delete the stale milestone bullet or add a follow-on gap (e.g. table/heading preservation) — current text is wrong as-written.
2. **Strengthen HTML parser fidelity beyond visible text.** `parsers/html.py:99-125` collapses everything into paragraph-joined visible text; links, headings, and tables are dropped, contradicting the production-grade fidelity the policy/news ingestion path will require.
3. **Add PDF OCR fallback for scanned documents.** `parsers/pdf.py:34-35` raises `ParserError("PDF does not contain extractable text.")` for any image-only PDF; no OCR adapter boundary exists, so scanned policy/claim PDFs are unparseable today.
4. **Surface per-row parser warnings for CSV/XLSX.** `parsers/csv.py` and `parsers/xlsx.py` are basic; there is no strict/permissive mode and no row-level malformed-data warning surfaced to operators despite the records pipeline depending on it.
5. **Add an outbox/recovery layer for storage-then-publish failures.** `ingestion/service.py:163-235` writes to object storage and then publishes `DocumentsUploadedEvent`/`DocumentsParsedEvent`/`DocumentsFailedEvent`; if the publish raises after the write, the document is stranded with no replay record.
6. **Introduce async I/O and worker backpressure for ingestion.** `IngestionService` in `ingestion/service.py:46-274` and `HttpxRemoteDocumentFetcher` in `parsers/remote.py:20-68` are fully sync, reading entire payloads into memory and blocking the event loop on large uploads or remote fetches.
7. **Harden remote document fetching against SSRF and oversized payloads.** `parsers/remote.py:20-68` enforces HTTPS-only and a single byte cap but has no host allowlist, no private-IP blocklist, no redirect-target re-check, no streaming download, and no authenticated-fetch story.
8. **Make extractor strategy and natural-key derivation explicit in config.** `extractor.create_document_extractor()` (`ingestion/extractor.py:438-468`) chooses Pattern vs LLM based purely on whether an `LlmClientProtocol` is injected; there is no `IngestionConfig.extractor.strategy` and no per-domain override, so operators cannot pin or A/B the extractor without DI surgery.
9. **Version and externalize LLM extractor prompts.** `LlmDocumentExtractor._build_prompt` (`ingestion/extractor.py:318-346`) hardcodes the system/user prompt strings and stamps `extraction_method="llm_v1"` with no prompt version tracked on candidates, so prompt edits silently change outputs and are not reproducible.
10. **Add JSON-mode retry, schema-coercion, and structured-output guardrails to the LLM extractor.** `_extract_chunk` (`ingestion/extractor.py:265-316`) does a single `generate()` call, strips only ` ``` ` fences, and on `JSONDecodeError` drops the chunk with a warning; there is no retry with a stricter prompt and no use of provider-native JSON/structured-output mode.
11. **Implement an LLM-backed fallback chain for extraction failures (provider exhaustion → pattern).** When `LlmProviderError` exhausts retries `LlmDocumentExtractor` simply returns `[]` warnings (`ingestion/extractor.py:285-286`); there is no chain that re-tries against `FallbackLlmClient` providers and then degrades to `PatternDocumentExtractor` for the chunk.
11a. **Implement cross-chunk relationship extraction.** Both extractors only emit intra-chunk relationships (`PatternDocumentExtractor._extract_relationships_from_chunk` at `extractor.py:162-203`; `LlmDocumentExtractor._extract_relationships` at `extractor.py:404-435`); entities co-occurring across chunks of the same document never produce relationships.
12. **Add same-document entity deduplication and fuzzy coreference for the pattern extractor.** `PatternDocumentExtractor` emits a fresh `CandidateEntity` per matching chunk (`extractor.py:144-159`), and the LLM extractor only dedups within a single chunk via natural key (`extractor.py:386-402`); cross-chunk merges and fuzzy coreference (for entities without a configured `natural_key`) do not exist.
13. **Add confidence thresholds with per-type calibration in validation.** `ExtractionResultValidator.validate_extraction` (`ingestion/validator.py:76-112`) accepts any confidence ≥ 0.0; there is no `IngestionConfig.confidence_thresholds` and no per-`EntityDefinition.name` override, so low-confidence pattern matches enter the graph.
14. **Add type-aware property normalization before `validate_entity`.** Validator at `ingestion/validator.py:23-37` passes raw extractor properties straight into `Entity`; there is no normalization pass for dates, decimals, booleans, enums, lists, or nested objects against `EntityDefinition.properties[*].type`, so ISO/regional date strings fall through to schema rejection or land malformed in the graph.
15. **Add upload policy enforcement at the ingestion-service layer (size, MIME sniff, format/extension/declared-type consistency).** API enforces `max_file_size_mb` and `allowed_content_types` (`api/routers/knowledgebases.py:402-421`), but `IngestionService.register_documents` (`ingestion/service.py:46-165`) trusts the submission's declared `content_type` with no byte-magic sniffing and no consistency check between `document_format`, extension, and declared content type; non-API callers bypass all of it.
16. **Wire document-level deletion to provenance-based graph/vector cleanup.** API delete uses `(filename, content_hash)` lookup and calls `graph_service.delete_by_source_document` / `vector_service.delete_by_source_document` (`api/routers/knowledgebases.py:430-439`); ingestion itself owns no `delete_source_document` / `reindex_source_document` contract, and the architecture.md §14.3 milestone "wire `delete_by_source_document` to the document-delete endpoint" remains open for the standalone document-delete route.
17. **Add ingestion-stage observability: structured logs, metrics, and trace spans.** `extractor.py` uses a module logger (`extractor.py:38`) but `service.py`, `chunker.py`, and `validator.py` emit no structured stage logs, no Prometheus counters/histograms (documents registered/parsed/failed, parse duration, extraction duration, dedup suppressions), and no OpenTelemetry spans around storage/parse/chunk/extract/validate/publish. Cross-edge to `_observability.md`.
18. **Add document-level status projection (`SourceDocumentStatusStore`).** `SourceDocument.status` exists at `ingestion/models.py:64` but there is no durable per-document status store, no monotonic transition log, and no per-KB document listing with current stage/error detail for the Ingestion Studio.
19. **Define extraction quality fixtures and golden tests with precision/recall gates.** `backend/tests/ingestion/fixtures/policies/` holds two markdown policy fixtures used only by the Ollama integration test (`test_documents_e2e_with_ollama.py:39`); there is no domain-coverage corpus (narrative PDF/DOCX, malformed files, multilingual samples) and no precision/recall metric computed against gold-standard extractions. Cross-edge to `analytics.md` / `_observability.md`.
20. **Add tenant-scoped ingestion namespacing.** `IngestionService` uses storage keys of the form `knowledgebases/{kb_id}/...` (`service.py:281,288,297,313`) with no `tenant_id` prefix; KB ids are assumed globally unique. Cross-edge to `_multitenancy.md`.
21. **Add multi-language support (chunking, extraction prompts, evidence handling).** `Chunk.language` field exists (`ingestion/models.py:130`) but is never set; `SentenceSplitter` (`chunker.py:187-245`) uses ASCII sentence terminators; the LLM extractor prompt (`extractor.py:333-339`) is English-only. Non-English documents are silently degraded.
22. **Add streaming upload + per-document progress reporting.** `register_knowledge_base_documents` awaits `upload.read()` into memory (`api/routers/knowledgebases.py:413`) and the synchronous ingestion service blocks on `object_store.put_bytes` (`service.py:93-103`); there is no chunked upload, no resumable upload, and no SSE/WS progress channel keyed on `source_document_id`.
23. **Add chunk-and-resume + memory-bounded handling for large documents.** `DocumentChunker.chunk_document` (`chunker.py:379-416`) materializes every chunk in a list before extraction begins; there is no streaming chunk pipeline, no per-document chunk count cap, and no resume-from-chunk-N path after a worker crash mid-extraction.
24. **Add a parser warnings channel on `ParsedDocument`.** `ParsedDocument.parser_metadata` is a free-form `dict[str, object]` (`models.py:92`); parsers (`pdf.py`, `docx.py`, `csv.py`, `xlsx.py`) have no typed `warnings: list[ParserWarning]` field to surface non-fatal issues (missing pages, dropped rows, charset fallback) up to the Ingestion Studio.
25. **Document and CI-enforce a production ingestion certification suite.** `backend/tests/ingestion/` covers unit + a single Ollama-gated integration test; there is no single `make ingestion-certify` target gating pyright/ruff/coverage/parser-fixture-corpus/provenance-round-trip/cleanup-reindex/extraction-quality, and no per-domain narrative-document fixture per architecture.md §6 ingestion requirements.

### Open questions

1. Is OCR (Epic 3) in scope for the platform endgame, or is the policy that scanned PDFs are rejected at ingestion until an external OCR pre-processor is run? Architecture.md §5/§6 does not explicitly commit to OCR.
2. Should fuzzy coreference (Epic 12) live in `ingestion/` or move to a new `analytics/entity_resolution/` module? `shared.types` does not currently expose a coreference contract.
3. Multi-language scope (Epic 21): is the immediate target English + Spanish for Medicare, or is the platform committing to a broader i18n posture? This shapes whether `Chunk.language` becomes a config-validated enum or a free-form ISO 639 code.
4. Streaming/resumable upload (Epic 22) — should chiliAI adopt `tus.io` resumable-upload protocol, multipart S3 directly, or a custom range-based POST? Architecture.md is silent; this is a UX/infra decision that affects `api.md` and `storage.md`.
5. Tenant scoping (Epic 20) — does the tenant id become part of the `source_document_id` natural key, or stay as a sibling field on every artifact? Affects content-hash dedup semantics across tenants.
