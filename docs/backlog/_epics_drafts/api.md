## File: docs/backlog/api.md

**Scope:** The `backend/api/` FastAPI gateway — application factory (`backend/api/app.py`), DI graph (`backend/api/dependencies.py`), frontend-facing read/write contracts (`backend/api/contracts.py`), seeded fallback state (`backend/api/state.py`), API-owned read projections (`backend/api/_alert_store.py`, `_workflow_projection.py`, `_kb_projection.py`, `_rag_bridges.py`), per-route routers (`backend/api/routers/*.py`), and middleware (`backend/api/middleware/{auth,rbac,metrics,policy_registry,session_store,exceptions}.py`). The api/ module is the only path the SPA hits — it owns request validation, DI wiring of every service module, the BFF session/OIDC flow, the SSE workspace stream, and the WebSocket hub. Per architecture §5.2 it must contain no business logic; cross-module epics here are about the boundary, not the underlying services.

### Epics
1. Replace the seeded `ApiState` fallback with real service-backed read paths — `backend/api/state.py` is a 1014-line hand-coded in-memory store (`ApiState.__init__` at `backend/api/state.py:128-195`) that seeds graph/risk/timeseries/explainability/RAG with literal Medicare entities (`provider-204`, `claim-8821`, `beneficiary-771` at `backend/api/state.py:135-139`) and is the live source for `/graph/entities/{id}`, `/evidence-packs/{id}`, `/cases/*`, `/policy/*`, `/chat/conversations/*`, `/analytics/overview|risk-scores/{id}|timeseries/{id}`; routers wire it via `Depends(get_api_state)` (`backend/api/dependencies.py:162-309`) and each `create_app()` clones a fresh instance (`backend/api/app.py:132`). The seeded data violates the "no hardcoded domain types" rule from CLAUDE.md and must be replaced with real graph/analytics/case-store-backed paths.
2. Wire the case store to a durable repository behind a protocol — `ApiState` holds cases, feedback, and policy gaps in process-local dicts (`backend/api/state.py:181-194`) with `Lock` guarding writes (`backend/api/state.py:265-294`); there is no `CaseRepository` protocol, no Postgres adapter, no migration, no cross-process state, and the `Co-Authored-By` cases lost on every API restart. `/cases` (`backend/api/routers/cases.py`) is fully functional only inside one process.
3. Wire the chat conversation store to a durable RAG conversation repository — `ApiState._conversations` is also a process-local dict (`backend/api/state.py:181-195`); `/chat/conversations` (`backend/api/routers/rag.py:42-105`) loses every analyst dialog on restart and cannot be load-balanced across workers. RAG-citation persistence and follow-up turns require a durable conversation store and a citation projection beyond the in-memory `_rag_bridges.py`.
4. Wire the policy-intelligence store to a durable repository — `/policy/gaps`, `/policy/gaps/{id}`, `/policy/gaps/{id}/cases`, `/policy/briefs` (`backend/api/routers/policy.py`) read and write to `ApiState._policy_gaps` (`backend/api/state.py:194`) with no persistence, no audit history, and no link to the real analytics or KB lifecycle.
5. Bridge the WebSocket hub to the Redis Streams event bus — `backend/api/routers/ws.py:4-7,89` documents the gap explicitly (`The actual bridge between the event bus (Redis Streams) and this hub is wired in Epic 8 — for now the hub accepts direct broadcast calls`); `WebSocketHub.broadcast` (`backend/api/routers/ws.py:118-134`) is process-local, so `/ws/alerts` and `/ws/pipeline` subscribers only receive events produced inside the same API process and only when test code or future bridge code calls `hub.broadcast(...)`. Coordinator-published `AlertCreatedEvent` / pipeline-stage events never reach connected SPAs.
6. Add WebSocket hub resilience and observability — beyond the missing Redis bridge, `WebSocketHub` keeps connections in a per-process `dict` with no per-connection backpressure, no slow-consumer eviction beyond `WebSocketDisconnect`/`RuntimeError` catches (`backend/api/routers/ws.py:131-134`), no max-clients cap, no metrics (`prometheus_client` counters in `backend/api/middleware/metrics.py:29` track only HTTP), no idle timeout beyond the 30 s ping (`backend/api/routers/ws.py:36`), and the `subscribe` filter is silently dropped on `ValidationError` (`backend/api/routers/ws.py:169-170,183-184`) without acking back to the client.
7. Replace the SSE polling loop with event-driven push and add reconnect semantics — `backend/api/routers/events.py:30-52` polls every 5 seconds (`await asyncio.sleep(5)`) and rebuilds the snapshot by calling `repository.list(limit=500)` + `agent_service.list_workflows(limit=500)` + `repository.count_active_alerts(...)` on every tick; there is no event-driven trigger, no Last-Event-ID resume / SSE `id:` field on yielded events (`backend/api/routers/events.py:50`), no per-client cap, and the only `max_events` knob is for tests (`backend/api/routers/events.py:41-42,56`).
8. Standardize the API error envelope across all routers — error responses are inconsistent: some routes raise `HTTPException(detail=str)` (`backend/api/routers/knowledgebases.py:158-161,193-195`, `backend/api/routers/alerts.py:46-49`), one route returns a 207 Multi-Status body shaped `{knowledge_base_id, pending_cleanup, steps[]}` (`backend/api/routers/knowledgebases.py:234-241`), KB busy errors map `KbBusyError → 409 detail=str(exc)` (`backend/api/routers/knowledgebases.py:200-204`), records routes funnel three exception classes to three different status codes (`backend/api/routers/records.py:95-107`), and mutations get a separate `ApiEnvelope{status,message}` model (`backend/api/contracts.py:11-15`). There is no `Problem+JSON` (RFC 7807) shape, no `error_code` field, no `correlation_id` echoed back, no `request_id`, and Pydantic 422 bodies still use FastAPI's default loc/msg/type shape.
9. Adopt a single Pydantic v2 contract package and remove the legacy/contract split — request/response models are split across at least four locations: `backend/api/contracts.py` (frontend-facing, ~37 models), `backend/api/routers/knowledgebases.py:54-91` (router-local `CreateKbRequest`, `DocumentRegistrationResponse`, `DocumentSummary`, `KbListResponse`, `DocumentListResponse`), `backend/api/routers/records.py:23-27` (`RecordPushRequest`), `backend/api/routers/ws.py:39-56` (WS subscribe filters), and service-layer `service_models.py` reused directly (`backend/api/routers/records.py:16` imports `RecordIngestReceipt`, `backend/api/routers/investigation.py:10-14` returns `graph.service_models.EntityDetailResponse`). The mix means contract evolution must touch multiple files, `openapi-typescript` (`chili_app/package.json:13`) consumes whatever name FastAPI emits, and there is no versioning boundary between `service_models` (internal) and `contracts` (external).
10. Adopt a consistent paginated-collection contract and apply it to every list endpoint — `AlertListResponse` returns `items[] + PageInfo{page,page_size,total_items}` (`backend/api/contracts.py:43-47`), `KbListResponse` returns `items[] + total` (`backend/api/routers/knowledgebases.py:67-71`), `WorkflowRunListResponse` returns `items[]` only with no total (`backend/api/contracts.py:269-272`), `EntitySearchResponse` is `items + total=len(items)` after the search already capped at `limit` (`backend/api/routers/investigation.py:114-115` — `total` is wrong when results are paged), and `/policy/gaps` returns `items[] + PageInfo` but the underlying `ApiState.list_policy_gaps()` ignores limit/offset (`backend/api/routers/policy.py:31-35`). No cursor pagination, no `next_cursor`, no `Link: rel=next`. The acknowledge endpoint returns `ApiEnvelope{status: "accepted"|"ok", message}` (`backend/api/contracts.py:11-15`) and is the only generic envelope.
11. Adopt a uniform filtering / sorting query convention — list endpoints accept ad-hoc query params: `/alerts` (`backend/api/routers/alerts.py:22-32`) takes none, `/workflows` accepts `knowledge_base_id`, `status`, `limit`, `offset` (`backend/api/routers/workflows.py:24-31`), `/knowledgebases` accepts only `limit`/`offset` (`backend/api/routers/knowledgebases.py:126-129`), `/investigation/search` uses `q`/`limit`/`offset` (`backend/api/routers/investigation.py:103-107`), and `/analytics/risk-scores` requires `kb_id` and accepts `entity_type` (`backend/api/routers/analytics.py:39-48`). No `?sort=`, no `?filter[severity]=`, no documented filter taxonomy, no shared `ListQueryParams` model.
12. Tighten OpenAPI schema quality (operation IDs, `response_model` everywhere, error responses, tags) — `backend/api/app.py:116-120` sets only `title`/`version`/`description`; routes have no `operation_id` set, so `openapi-typescript` (`chili_app/package.json:13`) generates names like `register_knowledge_base_documents_knowledgebases__knowledge_base_id__documents_post`; `/config/*` endpoints return `dict[str, object]` with no `response_model` (`backend/api/routers/config.py:24-44`); `add_message` declares `response_model=None` because it forks between JSON and SSE (`backend/api/routers/rag.py:65-77`) and OpenAPI cannot describe either branch; `/events/stream` returns `StreamingResponse` and is invisible to the schema (`backend/api/routers/events.py:55-82`); no router declares the 401/403/404/409/413/415/422/500 response shapes, so generated clients have no typed error branches.
13. Snapshot, publish, and lint the OpenAPI spec in CI — there is no checked-in `openapi.json` under `docs/` or `chili_app/`, no `make openapi-export` target, the only consumer is the manually-run `npm run codegen:api` (`chili_app/package.json:13`) which requires a running `http://localhost:8000/openapi.json`. No drift detection, no breaking-change checker (e.g. `oasdiff`), no `openapi-spec-validator`. Architecture §8.4 promises "the FastAPI backend auto-generates an OpenAPI specification" but the generated artifact is never persisted.
14. Adopt a versioning strategy for the public API — every router today is mounted at the bare resource path (`/alerts`, `/knowledgebases`, `/chat`, `/events`, `/ws`, etc.; see `backend/api/app.py:142-156`); there is no `/v1` prefix, no `Accept-Version` header, no deprecation banner, no sunset metadata. The SPA in the same repo consumes the latest schema directly, so breaking changes today only need a frontend update — that pattern breaks the moment a published API contract supports an integration (Plugin SPI, BFF for partner tooling, customer scripts, future mobile app).
15. Generate (and publish) a typed frontend API client from the OpenAPI spec — `chili_app/src/types/api.ts` is hand-maintained and `chili_app/src/lib/apiClient.ts` is hand-written; `chili_app/package.json:13` carries a `codegen:api` script that targets `http://localhost:8000/openapi.json` → `src/lib/api/schema.ts`, but `src/lib/api/` does not exist in the repo and `npm run codegen:api` is not run in CI. The hand-written client is allowed to drift from backend changes without any compile-time check.
16. Stand up backend↔frontend contract tests — there is no Pact / consumer-driven contract test, no schemathesis run, no `openapi-spec-validator` step, and the frontend `.spec.ts` files under `chili_app/e2e/` (`smoke.spec.ts`, `alert-feed.spec.ts`, `knowledge-base-list.spec.ts`, etc.) drive the real UI against a live API but do not assert response-shape parity with the OpenAPI document. The closest existing coverage is `backend/tests/api/test_read_model_routers.py` which uses FastAPI's `TestClient` to assert shape against `api.contracts` Pydantic models for a happy path only.
17. Move per-route policy declarations to a registry and audit on boot — every router today repeats `dependencies=[Depends(require_role("viewer"|"analyst"|"admin"))]` (40+ call sites across `backend/api/routers/*.py`); `backend/api/middleware/policy_registry.py:40-56 assert_complete` only checks each route has *some* `require_role` dependency by walking `route.dependant` for `_chiliai_required_role`, but cannot answer "list every admin-only endpoint", "what is the policy for `/workflows`", or "which routes changed policy between commits". The skip list (`SKIP_PREFIXES = ("/auth/", "/health", "/docs", "/openapi.json", "/redoc")` at `backend/api/middleware/policy_registry.py:12-18`) is hand-maintained. Move to a declarative registry that lists `(method, path, required_role, audit_event)` and have routes consume it; surface a `GET /policy/routes` for admin introspection.
18. Add rate limiting and abuse-control headers to the API gateway — there is no rate-limit middleware anywhere under `backend/api/middleware/`; the only middleware registered in `backend/api/app.py:122-135` is CORS + metrics + tracing instrumentation. No per-IP, per-user, or per-tenant throttle on `/auth/login` (`backend/api/routers/auth.py:58-90` — vulnerable to credential brute-force via the IdP callback loop), no upload-bytes-per-minute cap (`/knowledgebases/{id}/documents` accepts files up to `validation.max_file_size_mb` * N files per call — `backend/api/routers/knowledgebases.py:401-422`), no per-user open-WebSocket cap (`backend/api/routers/ws.py:99-108`), and no chat-message-per-minute cap on `/chat/conversations/{id}/messages?stream=true` (`backend/api/routers/rag.py:65-105`) which holds an LLM call open for the duration of the request. Cross-edge to `_security.md` and `_infra.md` (a Redis-backed token-bucket likely lives at the gateway/middleware level).
19. Split liveness, readiness, and dependency probes — `backend/api/app.py:137-139` defines a single `GET /health` that always returns `{"status": "ok"}` without checking event bus, graph repository, vector store, embeddings, object store, Postgres connection provider, or session store. There is no `/livez` vs. `/readyz` split, no per-dependency health surface, no warmup gate, no version/build-info endpoint, and no probe of `get_session_store()` Redis connectivity (`backend/api/dependencies.py:421-440`). K8s deployment manifests cannot distinguish "process is up" from "process is ready to serve traffic" and the `/health` route is also missing from the policy registry's skip-list audit reasoning (it works because the skip list at `backend/api/middleware/policy_registry.py:12-18` lists it).
20. Add request-correlation IDs propagated through logs, traces, and downstream events — `backend/api/app.py:106 setup_tracing()` calls into `shared.tracing.instrument_fastapi_app(app)` for OTel HTTP spans, but there is no middleware that reads/generates `X-Request-Id` / `traceparent` and propagates it onto `EventBase.correlation_id` (`backend/events/types.py:14-20`) when a route publishes an event (e.g. `/knowledgebases` publishes `KnowledgeBaseCreatedEvent` at `backend/api/routers/knowledgebases.py:115-117`). The `chiliai_session` cookie carries no per-request id, so a 500 traced in the API cannot be cross-correlated to the worker side. Cross-edge to `_observability.md` and `events.md` epic 5 (W3C Trace Context).
21. Plumb a per-request tenant context through middleware and into DI — there is no tenant axis anywhere in `backend/api/middleware/` or `backend/api/dependencies.py`; `User` (`backend/api/middleware/auth.py:52-58`) carries `user_id`, `roles`, `email` with no `tenant_id`. `get_api_state`, `get_knowledge_base_repository`, `get_alert_repository`, `get_workflow_run_store`, `get_graph_service`, `get_vector_store`, `get_session_store`, etc. (`backend/api/dependencies.py:162-808`) are process singletons keyed only by env/config, so even if a tenant claim were extracted from the JWT it has nowhere to flow. Hard cross-edge to `_multitenancy.md` (tenant binding source of truth) and `_security.md` (claim layout).
22. Surface BFF auth-flow gaps (CSRF, login state, logout RP-initiated flow, refresh storms) — `backend/api/routers/auth.py:90 build_authorize_url(...)` writes PKCE state only after the URL builds (good) but the cookie at `backend/api/routers/auth.py:163-172` is `SameSite=lax` with no double-submit-token / `_csrf` for state-changing endpoints; `/auth/logout` accepts a `post_logout_redirect_uri` query param with no allow-list (`backend/api/routers/auth.py:181-204` — open-redirect surface against the IdP `end_session_endpoint`); session refresh in `_maybe_refresh_session` (`backend/api/middleware/auth.py:251-298`) is per-request, not coalesced, so N concurrent requests near expiry will issue N refreshes; `JwksCache._clock=time.monotonic` (`backend/api/middleware/auth.py:89`) means the JWKS TTL is process-uptime-based, not wall-clock, which can hide rotation issues across restarts.
23. Harden the session store production surface — `RedisSessionStore.__init__` (`backend/api/middleware/session_store.py:87-108`) uses `decode_responses=True` and exposes no connect/socket timeout, no pool sizing, no TLS toggle, no health-check, no key prefix audit, and no session-revocation event. `InMemorySessionStore` (`backend/api/middleware/session_store.py:54-84`) carries a `# Thread-naive` warning in its docstring and is the default any time `AuthConfig.enabled=False` regardless of `CHILI_ENV` (`backend/api/dependencies.py:421-440`). Cross-edge to `_security.md` and `_infra.md`.
24. Open the closed `WorkflowRunResponse.workflow_type` enum — `backend/api/contracts.py:260-261` declares `workflow_type: Literal["ingestion", "graph_build", "analytics", "monitoring"]` and `backend/api/_workflow_projection.py:87-97 _workflow_type_for_trigger` maps every event prefix to one of those four; a new event family (e.g. `records.*`) is silently bucketed into `"ingestion"`. The closed `Literal` blocks adding workflow types without a coordinated frontend/contract change.
25. Add admin write surface for runtime config and ops actions — `backend/api/routers/config.py:18-21` carries a `TODO(production)` for `POST /config/domain` (update with validation), `POST /config/reload` (force reload), ETag / Last-Modified headers, and change-audit logging; `backend/api/routers/workflows.py:19-39` only mounts `GET /workflows` even though `AgentServiceProtocol` exposes `submit_workflow`, `cancel_workflow`, and DLQ listing (cross-referenced from agent.md Epic 19). There is no admin-only ops surface for DLQ replay, alert backfill, JWKS cache invalidation, session revoke, or hot reload.
26. Fix DI mis-wirings in `dependencies.py` flagged by the code today — `get_chat_message_payload` (`backend/api/dependencies.py:248-256`) calls `get_knowledge_base_repository()` directly without `Depends`, bypassing FastAPI's override mechanism and making tests unable to inject a fake KB repo for that path; `get_object_store()` returns `InMemoryObjectStore` only when `storage` section is at default (`backend/api/dependencies.py:447-453`) which silently switches storage backends if any non-default value is set; `get_session_store` is `@lru_cache(maxsize=1)` (`backend/api/dependencies.py:421-422`) but reads `os.environ["REDIS_URL"]` at first call — env mutations after the first call are ignored even by tests, and the cache is never cleared by `create_app()` (only `get_domain_config` is at `backend/api/app.py:110-111`).
27. Document the route surface (machine-readable + curated guide) — no `docs/api/` directory exists, the only API documentation is the auto-generated `/docs` (Swagger UI from FastAPI), and `docs/architecture.md` §8.4 references the OpenAPI spec but does not enumerate routes; the README.md files under `backend/` do not list endpoints. Need (a) an exported, version-controlled `openapi.json` (Epic 13), (b) a curated `docs/api/README.md` that lists every public route with its required role, request/response contract, error envelope, pagination and idempotency notes, and (c) a "deprecated routes" page once Epic 14's versioning lands.

### Open questions
- How much of `ApiState` (`backend/api/state.py`) is a true fallback that should disappear (Epic 1) versus a deliberate "demo seed" that should move to a `tools/seed_demo_state.py` script with the same data? Affects sequencing of Epics 1–4 and whether a feature flag (`CHILI_DEMO_SEED=true`) survives the rewrite.
- Are cases, conversations, and policy gaps in scope for the api/ module's persistence epics (2, 3, 4) or should they move to their own modules (e.g., `cases/`, `chats/`, `policy/`) under `backend/`? Affects file ownership and the boundary rules in §5.2.
- For the WS Redis bridge (Epic 5), do we keep one bridge per API process (each subscribes to the same consumer group with `XREADGROUP` and fans out to local clients) or run a dedicated bridge worker that publishes to API instances over a pub/sub channel? Architecture §4 mentions Redis pub/sub as a possibility but is non-committal.
- For SSE (Epic 7), do we keep `text/event-stream` as the primary transport or replace it with Server-Sent WebSockets / fetch-streams from the SPA? Affects reconnect semantics and the polyfill story.
- Error envelope (Epic 8): RFC 7807 `application/problem+json` (standard, but JSON-shape change for every client) vs. extend the existing `ApiEnvelope` model (`backend/api/contracts.py:11-15`) with `error_code` + `details` (less invasive but non-standard). Affects every router and the frontend apiClient.
- Pagination (Epic 10): cursor-based (`?cursor=...`) with opaque tokens, or stay with `?limit`/`?offset` and add a uniform `PageInfo` everywhere? Cursor is more robust at scale but rules out random-access UI; offset is what most existing routers already accept.
- Versioning (Epic 14): URL-prefixed `/v1/...` (cache-friendly, breaks every existing URL when v2 ships) vs. header `Accept-Version: 2` (cleaner URLs, harder for CDNs and gRPC bridges). Affects every router mount line in `backend/api/app.py:142-156`.
- Contract package (Epic 9): `backend/api/contracts/` (per-router submodules) vs. `backend/shared/contracts/` (importable by the SPA codegen consumer directly via OpenAPI). Affects whether `service_models.py` becomes purely internal.
- Tenant binding (Epic 21): tenant claim resolved from JWT vs. `X-Chili-Tenant` header vs. subdomain (`tenant-acme.chiliai.example.com`). Resolution affects `_multitenancy.md` Epic 1 and the BFF cookie domain (`backend/api/routers/auth.py:170` `domain=auth_config.cookie_domain`).
- Admin ops surface (Epic 25): does this become a separate `/admin/...` router family with its own RBAC tier ("super-admin") or stay folded into existing routers with `require_role("admin")`? Affects audit scope and the policy registry shape (Epic 17).
- For the route-policy registry (Epic 17), should the registry double as the auth source of truth (route → role) and remove the per-route `dependencies=[Depends(require_role(...))]` decorators, or sit alongside as a verification-only artifact? Removing the decorators makes the audit single-sourced but requires a new middleware to enforce policy from the registry on every request.
