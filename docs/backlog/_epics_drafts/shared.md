## File: docs/backlog/shared.md

**Scope:** Generic, leaf-level platform contracts library `backend/shared/` — domain-agnostic types (`Entity`, `Relationship`, `Alert`, `EvidencePack`, `KnowledgeBase`, `MonitoringObservation`), cross-cutting protocols (`Configurable`, `ObjectStoreProtocol`), provenance metadata constants, ID/clock utilities, stdlib-only validation helpers, structured logging and OpenTelemetry plumbing, alert severity normalization, and the dual-graph KB scope resolver. Per architecture §2.2 / §5.2 this module must remain dependency-light (stdlib + Pydantic + structlog + optional OTel only) and must never contain business logic or domain-specific types. Excludes any specific adapter logic (owned by each module's `adapters/`) and excludes auth/User/Tenant identity primitives at the protocol level (cross-edge into `_multitenancy.md` and `_security.md`).

### Epics
1. Promote `Alert.severity` from bare `str` to the canonical `AlertSeverity` Literal/enum — `Alert.severity: str` is annotated as bare string with an inline `TODO(production)` calling for a `SeverityLevel` enum, while `shared/alerts.py:7` already defines the `AlertSeverity = Literal["low","medium","high","critical"]` type that should be the typed surface (`backend/shared/types.py:117-119`, `backend/shared/alerts.py:7-22`); `monitoring/models.py:38,99` and `monitoring/service_models.py:53` also still type severity as `str | None`.
2. Retire the deprecated `Alert.acknowledged` flag in favor of the `status` Literal — `Alert.acknowledged: bool` lives alongside the canonical `status: Literal[...]` field and is explicitly marked deprecated in `backend/shared/types.py:124-129`, but no migration story removes it from the contract; every consumer still has to read/write both fields to stay consistent.
3. Enrich `EvidencePack` with the structured fields the analyst workbench expects — `EvidencePack` carries only `subgraph_nodes`/`subgraph_edges`/`scores`/`source_documents` with an inline `TODO(production)` for `timeline_events: list[TimelineEntry]` and `visual_layout: dict` (`backend/shared/types.py:134-148`); the explainability service today flattens `EvidencePack` into a bag of node/edge ids only (`backend/analytics/explainability/service.py:61-93`), and there is no timeline contract in shared yet.
4. Make platform-owned timestamps and `version` fields immutable / write-controlled — `Entity`/`Relationship` declare `created_at`, `updated_at`, `version` (`backend/shared/types.py:79-103`) but the validator drops them from the property comparison via a magic `platform_owned_fields = {"created_at", "updated_at", "version"}` set (`backend/shared/types.py:193`) instead of refusing them on input or owning the bump on update; today nothing enforces that adapters or extractors don't overwrite `version`/`updated_at` with stale values.
5. Centralize and harden entity ID generation conventions in `shared.utils` — `generate_id` is a UUID4 wrapper (`backend/shared/utils.py:10-12`) and is the only ID strategy across ingestion (`backend/ingestion/extractor.py:93,146,188,256,375,423`, `chunker.py:311,429`, `validator.py:105`), agent (`agent/service.py:47-48`, `workflow_tracking.py:31`), records, monitoring, vectorstore, knowledgebases, and API routers; there is no ULID/k-sortable option, no namespace prefix per entity kind, and no policy for stable IDs that survive re-ingestion (the `natural_key` field on `EntityDefinition` exists at `backend/shared/types.py:62` but `generate_id()` ignores it).
6. Add a typed exception hierarchy in `shared/exceptions.py` covering cross-module errors — `shared/exceptions.py:6-7` declares only `ConfigurationError(Exception)`; every module re-rolls its own root (`agent/exceptions.py:8`, `database/exceptions.py:6`, `embeddings/exceptions.py:6`, `llm/exceptions.py:6`, `monitoring/exceptions.py:6`, `records/exceptions.py:6`, `vectorstore/exceptions.py:6`, `graph/exceptions.py:6`, `rag/exceptions.py:6`), so API exception mappers cannot match a common base, and cross-module `NotFound` / `Conflict` / `Validation` errors are inconsistent.
7. Add shared pagination + filter primitives (`PageRequest`, `PageResponse`, `CursorPage`, `SortSpec`) — Nothing exists yet; every list endpoint re-derives `limit`/`offset` (`api/routers/knowledgebases.py:127-128,269-270`, `api/routers/investigation.py:106-107`, `api/routers/workflows.py:27-28`, `api/routers/analytics.py:47`) with no shared response envelope, no cursor-based option, and no shared `total`/`next_cursor` contract; the frontend has to special-case each endpoint.
8. Add a typed `Result`/`Either` primitive (or canonical exception protocol) for fallible boundary operations — Nothing exists yet; `validate_entity` and `validate_relationship` currently return `list[str]` of error messages (`backend/shared/types.py:173-265`) while every adapter raises exceptions; there is no shared type for "either a parsed value or a structured error" that ingestion validators, record validators (`records/validation.py:149`), and protocol callers can both consume.
9. Introduce a `Clock` protocol + `MonotonicTimer` wrapper and standardize on it instead of bare `time.perf_counter` / `datetime.now` — `utc_now()` lives in `shared/utils.py:15-17` but multiple call sites bypass it with raw `datetime.now(timezone.utc)` (`backend/api/state.py:964`, `backend/ingestion/orchestrators/source_documents.py:46`), and timing call sites import `time.perf_counter`/`time.monotonic` directly (`backend/monitoring/metrics.py:12,47,54`, `backend/api/middleware/metrics.py:6,60,74`, `backend/api/middleware/auth.py:17,89`); tests fake clocks ad hoc per module because there is no shared injectable clock.
10. Define the `TenantId` / `Tenant` primitive type and `tenant_id` field on platform types — Nothing exists in `backend/shared/` (verified by grep); `_multitenancy.md` epic 1 explicitly identifies this as a `shared/types.py` dependency. `Entity`, `Relationship`, `Alert`, `EvidencePack`, `KnowledgeBase`, `MonitoringObservation` (`backend/shared/types.py:79-371`) all lack a tenant binding; without the primitive here, every downstream tenant epic stalls.
11. Add a `KnowledgeBaseId` newtype, plus `domain_config_version`, `owner`, and `tags` on `KnowledgeBase` — `KnowledgeBase` has the inline `TODO(production)` for `domain_config_version: str | None`, `owner: str | None`, `tags: dict[str, str]` (`backend/shared/types.py:151-165`); there is no `KnowledgeBaseId` newtype, so the dual-graph `list[str]` scope returned by `resolve_kb_scope` (`backend/shared/kb_scope.py:29-64`) is untyped at every boundary it crosses.
12. Add `HealthCheckable`, `Lifecycle`, and `Measurable` cross-cutting protocols (and adopt them across services) — `shared/protocols.py:61-65` carries a `TODO(production)` to add `HealthCheckable.health_check()`, `Lifecycle.start/stop`, and `Measurable.get_metrics()`; today readiness probes can only ping the API itself and individual services have no uniform shutdown or metrics-export surface (`backend/embeddings/adapters/protocols.py:11-22` cites the same gap on `EmbedderProtocol`).
13. Move `MonitoringObservation` (and other scored-observation envelopes) behind a cleaner namespace and harden its docstring — `MonitoringObservation` was just promoted into `shared/types.py:356-371` per the recent commit but it sits below the validation helpers, is not exported from `shared/__init__.py:10-21`, and shares no parent with `EvidencePack`/`Alert`; the comment notes it lives in shared because both `monitoring/` and `records/` need it, but the file structure makes that intent fragile.
14. Add canonical UTC + ISO 8601 (de)serialization helpers — `utils.py:25-29` flags a missing `json_serialize(obj) -> str` with Pydantic + datetime handling; today the API relies on Pydantic's default JSON encoder, `EvidencePack.created_at` defaults via `utc_now()` (`backend/shared/types.py:143`) while `Alert.created_at` does not (`backend/shared/types.py:123`), and `PropertyType.DATE` validation accepts an ISO string but the codebase never standardizes how datetimes are serialized back out.
15. Extract the shared retry / backoff primitive promised in `utils.py` — `utils.py:25-29` calls out a missing `retry(max_attempts, backoff_factor, retryable_exceptions)` decorator; today `OpenAIEmbedder._create_embeddings_with_retry` (`backend/embeddings/adapters/openai_adapter.py:115-138`), `OpenAILlmClient`/`AnthropicLlmClient` adapters (`backend/llm/adapters/openai_adapter.py`, `anthropic_adapter.py`), and `agent.run_handler_with_retry` (recent commit a0a2a38) each implement bespoke backoff; cross-edge into `embeddings.md` epic 3 and `llm.md`.
16. Add a tighter validation surface — strict pyright on dynamic dict properties, registered custom validators, `extra="forbid"` defaults — `Entity.properties: dict[str, Any]` and `Entity.metadata: dict[str, Any]` (`backend/shared/types.py:84-85`) are deliberately open `Any` maps; `validate_entity` is the only enforcement and it runs at hand-selected boundaries (ingestion `validator.py:85,94`, records `validation.py:149`). 17. Add a `shared/README.md` (and `AGENT.md`) describing what belongs in `shared/` vs. what doesn't — `backend/shared/` has no README/AGENT files (verified `find`); the module-level docstrings in `__init__.py:1-5` and `types.py:1-9` carry the policy but it is invisible at the directory level. There is no pyright rule, ruff rule, or import-linter contract preventing `backend/shared/` from importing `config`, `api`, or any module package, and no AST/regex check forbidding domain identifiers like `Provider`/`Claim`/`Beneficiary` from appearing in shared/.

### Open questions
- ID strategy: do we keep UUID4 everywhere (current behavior, opaque, sort-unfriendly), move to ULID (k-sortable, debuggable), or adopt entity-namespaced stable IDs derived from `natural_key` (idempotent re-ingestion, but couples ID to config)? Epic 5's shape depends on the answer; the dual-graph contract makes opaque UUIDs harder to debug across KBs.
- `Result`/`Either` shape: `pydantic.BaseModel`-based generic (`Result[T, E]`) or a small `dataclass` with `is_ok`/`is_err`? Pydantic-backed is more consistent with the rest of shared/ but adds runtime cost on hot paths; a dataclass keeps it zero-overhead. Affects Epic 8 ergonomics.
- Tenant scope: is `TenantId` a `str` newtype (`NewType("TenantId", str)`), a UUID, or a structured `Tenant` Pydantic model with display name + status? Affects Epic 10 and every downstream multitenancy story.
- KB identifier: should we introduce `KnowledgeBaseId = NewType("KnowledgeBaseId", str)` and refactor every `kb_id: str` to that type, or accept the runtime cost / churn and stay with `str`? Epic 11 depends on this; cross-edge to `knowledgebases.md`.
- Exception hierarchy: introduce shared `ChiliError` root with `NotFoundError`/`ValidationError`/`ConflictError`/`PermissionError`/`ConfigurationError` and require every module's root error to inherit from it, OR keep flat per-module hierarchies and add an `api/`-side mapping layer? Affects Epic 6 surface area and the cross-edge into `api.md`.
- Pagination contract: offset/limit (current de facto) or cursor-based (better for high-cardinality KBs)? Mixed support means more boilerplate; the analytics + graph endpoints likely need cursors while config endpoints can stay offset. Epic 7 must pick.
- Clock injection: introduce a `Clock` Protocol consumed by services or rely on `freezegun` in tests? The former is cleaner but viral; affects Epic 9 reach.
- Severity policy: collapse the `monitoring/` `severity: str | None` cases to `AlertSeverity | None`, or treat `None` as an illegal request that should be rejected at the API boundary? Epic 1 needs a decision.
- Validation strictness: should `Entity.properties` switch from `dict[str, Any]` to `dict[str, JsonValue]` (where `JsonValue = Union[...]`) and reject non-JSON values at boundaries? Epic 16's ambition vs. churn tradeoff.
- CI guard mechanism: `import-linter` contracts (declarative, adds dep), a hand-rolled pytest collection check (zero deps), or pyright `extraPaths` + `reportImportCycles`? Epic 18 must pick before implementation.
- Logging/tracing optional-dependency boundary: structlog is a hard backend dep, OTel is optional via `[observability]` extra (`backend/shared/tracing.py:1-15`). Should `shared/` keep the soft import or formalize observability into its own subpackage so `shared/` itself stays dep-light? Affects Epic 12 and Epic 17 placement.
